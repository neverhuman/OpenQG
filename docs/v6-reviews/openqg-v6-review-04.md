# Mechanism-off twin and novelty tiers

V6.1's novelty design is a major improvement over V5. `crates/openqg-core/src/theory/binding.rs::audit_novel_predictions_with_context` computes the witness prediction using `BackgroundForwardModel` on the bound background. It computes a LambdaCDM baseline. It also computes a "mechanism-off" twin through `binding.rs::mechanism_off`, then checks whether the witness is distinct from that twin rather than from a completely different background. This closes the drift-bought `cmb_lA` witness path: if a background drift changes `lA`, the same drift remains in the twin and cancels.

The implementation is still incomplete as a GR-limit reset. `mechanism_off` sets `mu0 = 0`, `drag_a = 0`, `mg_family` to the Planck reference family, `ndgp_omega_rc = 0`, `fr_n` to the reference value, and `fr_log10_fr0` to the reference value. It intentionally leaves standard background coordinates alone. That is right for isolating growth mechanisms from background drift. But it does not reset all possible mechanism-bearing fields. It leaves `w0`, `wa`, `sigma8`, `n_eff`, `sum_mnu`, and `omega_k` unchanged. That is fine if those are priced as background, normalization, or standard cosmological coordinates; it is not fine if a future relation treats `w0/wa` as part of a dark-sector mechanism or lets `sigma8` absorb growth. In the current code, `dark_scattering_growth_drag` depends on `w0` through `growth_drag_gamma`, but the twin only switches `drag_a` off and leaves the same `w0`. That isolates drag, but a dark-scattering proposal can still pay one background dof and make most of the observational shift come from `w0`, then claim the residual as mechanism novelty.

The bigger issue is tier value. `scorecard.rs::score_with_observables` awards full novelty only for a computed, honest, distinct, out-of-fit-set, non-engine-refreshed witness. That is the right top tier. It awards 0.5 for an engine-refreshed out-of-fit-set witness and 0.25 for a fit-set witness. The 0.5 tier is defensible as a falsifiable prediction that the engine authored during re-clothing; it should not be called proposer-authored novelty. The 0.25 fit-set tier is harder to defend. A witness on data already scored in the likelihood is an explanation of fit, not a novel prediction. Awarding 5 points for it leaves a positive reward for self-validation.

The measurement floor is also context-limited. The code sets `sigma_floor_obs` only when the witness observable matches a scored `fit_observables` record. For out-of-fit-set witnesses, `min_detectable` remains proposer-supplied. The honesty tolerance is clamped as `min(min_detectable, 1 percent of computed predicted value)`, but distinctness still compares against `min_detectable`. A model can choose a tiny out-of-fit threshold and get distinctness for a numerically negligible mechanism difference, provided it learns the exact predicted value through repair or examples.

There is also a coherence gap between claim obligations and novelty audits. `score_with_observables` runs `obligation_vetoes`, but `DerivationObligationKind::NovelPrediction` is not a derivation proof in the same sense as a numeric witness. A proposal can include a physics claim whose obligations list contains a numeric relation and a novel witness, and the rigor score is computed from the best verified obligation. That is fine. But the novelty witness itself can be unconnected to the mechanism relation except through the bound background. V7 should require a witness to name the mechanism field it is meant to test, then verify the mechanism-off delta flows through that field.

Recommended changes: in `binding.rs`, replace `mechanism_off(bg: &CosmologyParams)` with a typed reset driven by the binding report: `mechanism_off(bound_background, bindings)`. Reset only fields introduced by verified bindings, and record which fields were reset. For dark scattering, reset `drag_a` and preserve `w0` but mark the novelty attribution as "drag conditional on background w0". For nDGP and f(R), reset the family-specific fields and require action terms in the structural veto.

In `scorecard.rs`, set fit-set witness novelty to 0.0 and add a separate non-scoring `fit_explanation` field in `NovelPredictionAudit`. Reduce engine-refreshed novelty from 0.5 to at most 0.25 unless the witness was registered before the descendant fit. Add a global observable registry with measurement sigmas so out-of-fit witnesses cannot pick their own resolution. Finally, add a regression test where an out-of-fit witness with `min_detectable = 1e-12` is denied novelty unless the observable exists in that registry with a real experimental threshold.
