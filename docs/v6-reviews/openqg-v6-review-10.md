# StructurallyUngenerated veto and term grammar

`StructurallyUngenerated` is the right idea and the wrong implementation. The V6.1 audit found that proposals could turn background or alpha dials without action-level structure. The current fix is in `crates/openqg-core/src/theory/vetoes.rs::adjudicate`. It collects term names as strings, computes `has_de_dynamics` by checking whether any term name contains substrings such as `quintessence`, `scalar`, `dark_energy`, `k_essence`, `galileon`, `drag`, or `coupling`, and then kills dynamic `w0/wa` if no such term exists. It separately kills alpha-basis deviations if no dark-energy dynamics and no term name containing `gauss` or `horndeski` exists.

This is a useful emergency patch. It is not a term algebra. Substring matching has both false positives and false negatives. A fake term named `quintessence_decoration` or `scalar_placeholder` can satisfy the check without representing a kinetic term, potential, coupling, or stress-energy contribution. A legitimate term with a name outside the substring list can fail. More importantly, the current check does not cover the derived modified-gravity families that the binder introduces.

The survivor demonstrates the gap. In `run-data/v6-chunk-6-white-paper.json`, `ndgp-proposed-fixed-rc` has only two terms: `einstein_hilbert` and `cosmological_constant`. Its parameter `geff_over_g` is certified by `ndgp_geff_over_g`. During scoring, `crates/openqg-core/src/theory/binding.rs::bind_modified_background` sets `mg_family = Ndgp` and `ndgp_omega_rc = 0.7097028068896183`. `physics_kills` does not reject this missing nDGP structure. The candidate is therefore a bound nDGP growth modification wearing a GR action term list.

The same issue exists for f(R) and coupled dark energy. `binding.rs` can set `mg_family = FrHuSawicki`, `fr_n`, and `fr_log10_fr0` from `fr_alpha_m`; it can set `mu0` from `coupled_de_geff_over_g`; it can set `drag_a` from `dark_scattering_growth_drag`. The structural veto should require corresponding term kinds, not just any term containing `drag` or `coupling`. The relation registry in `crates/openqg-core/src/theory/certificate.rs` already knows the relation names. V7 should use that relation identity to demand term structure.

A real term algebra does not need to be a full symbolic CAS on day one. It needs typed term families and required capabilities. Replace `Term { name, mass_dimension, free_lorentz_indices }` with, or augment it by, a typed enum such as `TermKind::EinsteinHilbert`, `CosmologicalConstant`, `CanonicalScalar`, `KEssence`, `Horndeski`, `FRHuSawicki`, `DgpBrane`, `DarkSectorMomentumExchange`, and `GaussBonnet`. Keep `name` as display text, not policy. Add fields for `generates_background_w`, `generates_alpha`, `generates_mu0`, `generates_ndgp`, `generates_fr`, and `generates_drag`, or derive these from the enum.

Then add a relation-to-term map. `ndgp_geff_over_g` and `ndgp_beta_from_omega_rc` require `TermKind::DgpBrane`. `fr_alpha_m` and `fr_largescale_geff_over_g` require `TermKind::FRHuSawicki`. `dark_scattering_growth_drag` requires `TermKind::DarkSectorMomentumExchange` plus a non-phantom `w0`. `coupled_de_geff_over_g` requires a coupled scalar or dark-sector coupling term. `planck_mu0_geff` is a phenomenological parameterization; it should require an admitted phenomenological MG term and should not earn full mechanism rigor.

The term algebra should also connect to certificates. If `bind_modified_background` sets a field, the binding report should include `required_terms`. `physics_kills` should compare those requirements to `theory.terms`. This avoids duplicating policy across binder and veto layers. It also prevents direct-symbol binding from evading structure: a fundamental `ndgp_omega_rc` parameter should still require a DGP term.

Add tests at the exact exploit surface. In `vetoes.rs`, add `ndgp_binding_without_dgp_term_is_structurally_ungenerated`, using a theory like the survivor: baseline terms plus certified `ndgp_geff_over_g`. It should be killed. Add `fake_quintessence_decoration_does_not_generate_w0`, where a term named `quintessence_decoration` is not enough unless its typed kind is `CanonicalScalar` or equivalent. Add `dark_scattering_requires_drag_term`, where a certificate binds `drag_a` but the term list lacks `DarkSectorMomentumExchange`.

Longer-term, the grammar should carry equations or operators, not only term kinds. But typed generation capabilities are the minimum credible V7 fix. The current substring check is a useful regression patch, but it is too easy to game and too narrow to protect the modified-gravity sectors the engine actually rewards.

One final rule: action terms should not be introduced automatically by the mutation or proposal conversion layer when the scientific claim is that the proposer derived them. `crates/openqg-core/src/theory/proposal.rs::proposal_into_theory` currently appends `horndeski_scalar` or `quintessence_scalar` for some dials. That is acceptable for deterministic mutation hygiene, but a live proposal should carry the term explicitly and have its claim graph certify it. Otherwise the engine is silently completing the Lagrangian for the model.
