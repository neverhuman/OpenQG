# Truth-binding audit

`crates/openqg-core/src/theory/binding.rs::bind_modified_background` is the right conceptual layer: it translates verified certificates into the `CosmologyParams` fields consumed by `BackgroundForwardModel` and the growth solver. The relation precedence is explicit: relation certificates first, direct-symbol copies second, declared-background reconciliation third, unimplemented distinct certificates last. The new kill classes in `vetoes.rs` are also well chosen: `UnimplementedModification`, `UnexplainedModification`, and `ConflictingModification` describe the actual failure modes.

The nDGP inversion is mostly consistent with `crates/openqg-core/src/theory/sectors/ndgp.rs`. The sector defines `beta = 1 + (E/sqrt(omega_rc))*(1 + dlnE/dN/3)` and `mu = 1 + 1/(3 beta)`. `binding.rs` inverts a verified `ndgp_geff_over_g` certificate by taking `beta`, computing `factor = E1*(1 + d1/3)`, then `omega_rc = (factor/(beta-1))^2`. That is algebraically correct for the implemented normal-branch formula. The domain check `beta > 1` is stricter than merely healthy `beta > 0`, but for late-time LCDM-like backgrounds `factor > 0`, so beta should indeed exceed 1 for positive `omega_rc`. The code correctly kills `beta <= 1` as unbindable/ghost-branch.

The direct `ndgp_beta_from_omega_rc` path is less complete. It verifies the certificate value through `certificate.rs::ndgp_beta_from_omega_rc`, but binding then uses only `cert_input(cert, "omega_rc")`. It does not independently recompute that the certificate's optional `omega_m`, `w0`, and `wa` inputs match the theory's own background. A malicious proposal can certify beta for one background and bind `omega_rc` into another, relying on the relation name to earn rigor. Mitigation: at binding time, reject any certificate input that names a background coordinate and disagrees with `theory.background` beyond tolerance.

The f(R) inversion deserves a stronger caveat. `binding.rs` inverts `fr_alpha_m` using `n = (a_f_R_prime/f_R)*(omega_m + 4 omega_de)/(3 omega_m) - 1` and `log10_fr0 = log10(abs(f_R))`, then `growth.rs` computes Hu-Sawicki response via `FrParams::response`. This is a tracking approximation at `a=1`, not a full proof that the same `n, f_R0` generate the supplied derivative over the relevant redshift range. It should bind with a fidelity note and require `0 < omega_m < 1`, `omega_de > 0`, `f_R > -1`, and a scalaron mass/stability domain check. Right now `omega_de` is clamped with `.max(1e-9)`, which can hide an unphysical closure during inversion.

`planck_mu0_geff` is honest but too permissive for scoring. `certificate.rs::planck_mu0_geff` verifies only `G_eff/G = 1 + mu0` today with `mu0 > -1`. `growth.rs::growth_mu` then imposes `mu(a)=1+mu0*Omega_DE(a)/Omega_DE0`. That is a phenomenological parametrization, not a mechanism; the rigor weight 0.3 is appropriate. The binder should not let a direct fundamental `mu0` bypass that low rigor by using the direct-symbol path.

The coupled-dark-energy path is intentionally approximate but under-policed. `binding.rs` maps `coupled_de_geff_over_g` to `mu0=2 beta^2` with an amplitude-only fidelity note. That always enhances growth and cannot express the V5 suppressed-growth direction. It also conflicts physically with the Planck `mu0` time dependence unless the coupling model is explicitly reduced to that ansatz. Require a `fidelity` penalty in scoring, not just a note in `BindingReport`.

The largest practical bug is that `adjudicate` is not composed into scoring. `vetoes.rs::adjudicate` would reject several alpha/screening states the binder does not address. The V5 champion has `screening_recovery=null`; `adjudicate` would emit `ScreeningRecoveryUnquantified`, but the scorecard path calls only `run_veto_cascade`. V6 should introduce one public `physics_kills(theory)` function that concatenates triage, adjudication, and binding vetoes, then replace all callers of `run_veto_cascade` in scoring/evaluation with it.

Add regression tests directly from the archive. Deserialize `run-data/v5-chunk-1-white-paper.json`'s champion theory into `Theory` and assert that the V6 gate rejects it until `screening_recovery` is supplied and background/parameter inconsistencies are repaired. Add another test for a clean `planck_mu0_geff` theory with `mu0=-0.1`, alpha all zero, and an honest witness, and assert it still binds and scores. That prevents the fix from simply killing the new suppressed-growth vocabulary.

Also expose binding precedence in the receipt. The current `BindingReport.bindings` records sources, but conflicts that arise from relation-versus-direct-symbol precedence are only stringified in `veto_notes`. V6 should serialize typed binding vetoes so downstream memory and dashboards can distinguish "relation unbindable", "direct symbol disagrees", and "declared background unexplained" without substring matching.
