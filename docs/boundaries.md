# Boundaries

OpenQG boundaries are controlled by agent-readable maps:

- `agent/owner-map.json` assigns ownership
- `agent/test-map.json` assigns proof routes
- `agent/generated-zones.toml` lists generated or regenerated zones
- `agent/boundaries.toml` lists editable and forbidden paths

Current contract boundary rules:

- edit contract sources in `contracts/specs/`
- edit the registry in `contracts/registry.yml`
- regenerate outputs with `just schema-sync`
- verify generated outputs with `just schema-check`
- do not edit `contracts/generated/schemas/` by hand
- contract witness receipts live under `target/openqg/contracts/` and are generated by `just schema-check`

Generated and review-only zones:

- do not edit `target/` by hand
- do not edit `reports/releases/draft/` by hand
- do not edit `contracts/generated/` by hand
- keep Jekko previews and daemon receipts under `target/openqg/zyal/` and `target/openqg/research/`
- keep human review receipts under `target/jankurai/review/`

DB policy surface:

- `db/` is policy-only for now; the canonical guidance lives in `db/README.md`, `db/migrations/README.md`, and `db/constraints/README.md`
- OpenQG currently has no production DB migrations
- future DB work must define migrations, rollback and backfill plans, foreign keys, check constraints, row-level security, lock safety, and monitoring before any runtime path depends on it

Research artifacts are split by durability:

- `research/inbox/` holds reviewable candidate cards
- `research/knowledge/` holds curated synthesis maps and claim ledgers
- raw provider receipts, daemon ledgers, and run state stay under `target/openqg/research/`
