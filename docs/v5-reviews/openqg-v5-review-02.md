# Gameability red-team of the V5 rubric

The strongest new cheat is not in truth-binding; it is around it. V5 binds certified modified-gravity claims, but the rest of the scorecard still rewards cheap structural signals. The run-data champion demonstrates this. In `run-data/v5-chunk-1-white-paper.json`, the theory has nonzero `alpha_m`, `alpha_b`, and `alpha_k`, a bare `screening` label, and no `prediction_audits`. It receives `novel_prediction=10`, `parsimony=12`, `robustness_under_judge=13`, and `free_dof=0`. The model can therefore earn half novelty and full parsimony without deriving the alpha sector or quantifying screening.

Cheat 1: direct-symbol `Fundamental` binding. In `crates/openqg-core/src/theory/binding.rs`, direct symbols named `mu0`, `ndgp_omega_rc`, `fr_log10_fr0`, and `fr_n` are copied into the background when their provenance is `Fundamental` or verified `Derived`. Because `scorecard.rs::free_dof` treats `Fundamental` as free of cost, a proposer can call a new gravity knob "fundamental" and receive a computed modified background without paying the parsimony ledger. Mitigation: define a registry of admitted fundamental constants. A direct-symbol MG field should require either a relation certificate or an explicit "new fundamental constant" cost. Add `background_free_dof(theory)` and count every non-baseline cosmological or MG background coordinate unless tied by a verified relation.

Cheat 2: background overrides bypass provenance. `proposal.rs::BackgroundProposal` accepts `h`, `omega_m`, `omega_b_h2`, `n_eff`, `sum_mnu`, `w0`, and `wa`; `proposal_into_theory` writes them straight to `CosmologyParams`. Mutations in `mutation.rs::mutate` also move `background.h`, `omega_m`, and `w0`. None of these are counted by `free_dof`, and they need no claim obligation. Mitigation: either remove mutable background fields from `Theory` and derive them from `Parameter`s, or mirror every non-baseline background field into a provenanced parameter during scoring. `H0` and `Omega_m` in `Theory.parameters` must be synchronized with `background.h` and `background.omega_m`; current white papers show they are not.

Cheat 3: half novelty for alpha jitter. `scorecard.rs` sets `nov_raw=0.5` when `physically_distinct` is true and `prediction_audits.is_empty()`. `distinct_from_lcdm` returns true for any `theory.modifies_gravity()`, and `Theory::modifies_gravity` is just `alpha.modification_scale() > 1e-6` or nonzero `alpha_t`. A child can jitter `alpha_m` by tiny amounts, declare a screening string, and bank 10 points even if no observable is computed from alpha. Mitigation: no witness means zero novelty. If the team wants a "distinct but untested" diagnostic, record it outside the weighted score.

Cheat 4: witness-controlled honesty tolerance. `binding.rs::audit_novel_predictions` uses `w.min_detectable` both for distinctness and honesty tolerance. An adversarial witness can inflate `min_detectable` until its false declared `predicted` and `baseline` fall within tolerance. It then risks losing `computed_distinct` if the threshold exceeds the computed difference, but it can tune threshold just above the lie and below the model difference. Mitigation: split fields into `experimental_resolution` and `honesty_tolerance`; clamp honesty tolerance by an engine constant or dataset-specific uncertainty, not by proposer text.

Cheat 5: uncomputable witness half-credit. If all prediction audits have `computed_distinct=None`, `scorecard.rs` awards `nov_raw=0.5`. A proposer can use an unrecognized observable id to get the same half novelty as no witness. Mitigation: uncomputable witnesses should be a demotion to 0 or a separate "unsupported novelty" note. At minimum, require one computable witness for any novelty points.

Cheat 6: robustness is just split stability. `scorecard.rs` maps `generalization_gap` through `1/(1+gap/0.05)`. `held_out_evaluate` uses an alternating split over the same admitted observables; the V5 champion has `generalization_gap=0.0` across chunks. This is not an adversarial judge, external dataset, or covariance stress. Mitigation: define robustness as min over declared stress suites: covariance perturbation, leave-one-survey-out, high-z holdout, and shifted priors.

Cheat 7: memory poisoning. `proposer_memory.rs::assemble_memory` mines ledgers into prompt directives. A high-scoring but flawed class can become a repeated "DO" by entering the top-scorer memory. Mitigation: memory should only summarize candidates that pass the same V6 promotability gate and should carry diversity quotas.

Cheat 8: declared screening as a pass token. `run_veto_cascade_full` only checks `MissingScreening` when `theory.screening.is_none()`. A nonempty string is enough for triage. The stricter `adjudicate` path would demand `screening_recovery`, but scoring does not call it. Mitigation: either move quantified screening into triage for all scored candidates, or make `score_candidate` call a new combined gate. A string label should never be enough to keep alpha-basis gravity modifications alive.
