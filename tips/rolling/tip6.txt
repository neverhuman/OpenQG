Yes — I think your instinct is right. For **Phase 0**, trying to “discover a unified theory and beat real data” is probably too blunt and too easy to Goodhart. The better first target is a **self-improving research gym** where one population tries to create ambitious theories and another population tries to make the scoring discipline sharper, more hostile, more derivation-aware, and less gameable.

I would build it as a **coevolutionary research lab**, not a single benchmark.

My proposed name for the system:

# **OpenQG Forge: Hero–Judge Coevolution for Derivation-First Physics**

The core idea:

[
\textbf{Do not optimize for “score.” Optimize for “new closed derivations per free knob.”}
]

A hero theory should win only when it turns an unsupported row family into a **derivable, auditable, fixture-independent prediction**. A judge rubric should win only when it catches fake derivations while still recognizing real mathematical compression.

## 1. What OpenQG currently gives you

The public `neverhuman/OpenQG` repo is already pointed in the right direction, but it is still much closer to **control-plane scaffold** than finished scientific benchmark.

The README says OpenQG is an “evidence-gated benchmark and control plane for interpretable unified-physics theories,” with baseline physics anchored to `SM + GR + LambdaCDM + massive neutrinos`, typed manifests, reproducible smoke data, explicit scores, and auditable release receipts. Its surface map includes Rust crates for typed manifests, data/fixture validation, benchmark orchestration, contracts/schemas, benchmark suites, theory manifests, and runnable research/maintenance loops under `agent/zyal`. ([GitHub][1])

The mission statement is very important: OpenQG is trying to answer which candidate theory families reproduce public low-energy data better than the `SM+GR+LambdaCDM` baseline while staying interpretable; it explicitly says it is **not** claiming quantum gravity is solved, not a black-box model zoo, and not a place for raw data dumps or undocumented fit knobs. ([GitHub][2])

Right now, though, the current smoke benchmark is tiny. The smoke suite contains only `h0`, `omega_m`, and `sum_mnu`, with dataset IDs `nist-codata-constants` and `planck-legacy-cosmology`; the full umbrella suite still points to the same smoke fixture predictions while listing broader registry-backed dataset families. ([GitHub][3]) The committed smoke observations are Planck-style values for (H_0), (\Omega_m), and (\sum m_\nu), and the committed baseline predictions duplicate those fixture values. ([GitHub][4])

That means the current benchmark is useful as a **regression and plumbing lane**, not yet as a serious discovery test.

The scoring code is also still intentionally simple. It computes Gaussian log likelihoods, coverage, AIC, BIC, MDL, parameter penalties, and invalid prediction findings, then maps the score mostly from coverage plus positive delta log-likelihood minus parameter and invalid-prediction penalties. ([GitHub][5]) The docs similarly say the current score derives from smoke benchmark factors including coverage, missing predictions, invalid prediction count, and parameter-count penalty. ([GitHub][6])

The best existing admission principle in the repo is this: a candidate theory must provide a stable id, citations, observables, named parameters, and an adapter command; every parameter needs a unit, meaning, prior/fixed value, and a reason the value is fixed or free; gray-box optimizers should not be promoted. ([GitHub][7])

So the repo already has the right bones. The missing Phase‑0 upgrade is: **turn prediction records into proof-carrying scientific claims.**

# 2. The real Phase‑0 objective

I would not start with “beat all real data.”

I would start with:

[
\boxed{
\text{Can agents produce, attack, and improve derivation-carrying theory artifacts?}
}
]

The Phase‑0 benchmark should reward:

1. **Clean theory artifacts**: primitives, action/equivalent object, constants ledger, row map, falsifiers.
2. **Strict refusal discipline**: unsupported rows must be refused, not guessed.
3. **Proof-carrying predictions**: any emitted value must include derivation provenance.
4. **Novel compression attempts**: new invariants, no-go theorems, classification arguments, row adapters.
5. **Judge hardening**: rubrics must improve at separating real derivations from formal decoration.

Only later should OpenQG become a large public-data competition.

For now, the central unit is not the empirical row. It is the **claim certificate**.

# 3. The coevolution model

You want two populations:

## Population A: **Hero agents**

Hero agents try to produce the most ambitious candidate theory artifact possible.

They are rewarded for:

[
\text{new derivations}
+
\text{structural compression}
+
\text{closed prediction rows}
-----------------------------

## \text{free parameters}

## \text{unjustified state inputs}

\text{leakage risk}.
]

A hero cannot win by writing a beautiful theory. It wins by closing previously open proof edges.

## Population B: **Judge agents**

Judge agents try to make the benchmark harder, cleaner, and less gameable.

They are rewarded for:

[
\text{catching fake derivations}
+
\text{discovering hidden knobs}
+
\text{improving row semantics}
+
\text{creating adversarial tests}
+
\text{preserving recognition of real progress}.
]

A judge cannot win by being cynical about everything. It wins by producing a rubric that correctly separates:

```text
real derivation
known human structure
conditional formalism
parameter fitting
source-state leakage
benchmark overfit
plain hallucination
```

The key is that **heroes and judges evolve separately**, but a third layer freezes and audits the rules.

# 4. The architecture I would build

The system should have five layers.

```text
OpenQG Forge
├── 1. Literature + claim commons
├── 2. Hero foundry
├── 3. Judge foundry
├── 4. Verifier layer
└── 5. Governance / release layer
```

## Layer 1: Literature + claim commons

This is a structured memory of prior human and agent work.

It contains:

```text
papers/
claims/
constants_ledgers/
row_semantics/
known_theories/
known_failures/
benchmark_canaries/
formal_theorems/
source_state_rules/
```

Every theory claim becomes a structured object:

```json
{
  "claim_id": "ncg_generates_sm_lagrangian_form",
  "claim_type": "structural_derivation",
  "theory_family": "spectral_ncg",
  "statement": "The almost-commutative spectral action generates the SM Lagrangian form once the finite algebra is chosen.",
  "inputs_required": ["finite algebra", "finite Hilbert space", "Dirac operator data"],
  "free_parameters": ["finite Dirac/Yukawa matrices", "spectral action moments", "cutoff"],
  "row_consequences": [],
  "status": "known_human_structural_claim",
  "evidence": ["primary literature", "review literature"],
  "failure_modes": ["does not derive alpha", "does not derive Yukawa eigenvalues", "does not derive cosmological state"]
}
```

This lets the system reason about **claim types**, not just theory names.

## Layer 2: Hero foundry

The hero foundry should have many specialized agents, not one “genius” prompt.

I would run at least these hero roles:

| Hero role                | Output                                                                                                                  |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| **Primitive searcher**   | Candidate foundational principle, e.g. anomaly closure, index theorem, fixed point, compactness condition, causal rule. |
| **Theory architect**     | Action/equivalent formal object, degrees of freedom, symmetry content.                                                  |
| **Constants accountant** | Constants ledger: derived, free, structural, environmental, metrological.                                               |
| **Row adapter engineer** | JSONL prediction/refusal adapter.                                                                                       |
| **Formalizer**           | Converts claims into Lean/Coq/SymPy/Sage/SMT-checkable pieces when possible.                                            |
| **Phenomenology mapper** | Maps theory claims to OpenQG row families.                                                                              |
| **No-go miner**          | Looks for impossibility theorems that are themselves valuable.                                                          |
| **Synthesis agent**      | Merges compatible fragments without hiding free parameters.                                                             |

The hero output must be a complete artifact, not just prose.

Minimum hero artifact:

```text
theory.md
manifest.yml
constants-ledger.yml
claims.jsonl
prediction-policy.yml
adapter/
proofs/
falsifiers.md
refusals.jsonl
literature-map.md
```

## Layer 3: Judge foundry

The judge side should be more elaborate than the hero side.

Recommended judge roles:

| Judge role                   | Function                                                                                         |
| ---------------------------- | ------------------------------------------------------------------------------------------------ |
| **Leakage auditor**          | Finds fixture leakage, copied constants, benchmark tuning, hidden calibration.                   |
| **Constants prosecutor**     | Attacks (\alpha), Yukawas, CKM, PMNS, (\Lambda_{\rm QCD}), (v), vacuum energy, source states.    |
| **Row-semantics judge**      | Checks whether the row actually matches the claimed prediction object.                           |
| **Formal consistency judge** | Looks for anomalies, unit errors, gauge inconsistency, nonrenormalizable claims, invalid limits. |
| **Literature judge**         | Verifies that claimed “known theory” claims are actually in the literature.                      |
| **Novelty judge**            | Distinguishes new compression from renamed known structure.                                      |
| **Rubric engineer**          | Proposes scoring changes based on failure cases.                                                 |
| **Canary judge**             | Tests the rubric against known-good, known-bad, and known-honest-baseline artifacts.             |

The judge output should not merely be a score. It should include **patches to the benchmark discipline**.

Example judge output:

```json
{
  "artifact_id": "NCG-SSM-OQG-v1",
  "verdict": "strong_structural_theory_not_strict_data_predictor",
  "accepted_claims": [
    "SM_lagrangian_form_from_spectral_action_given_finite_geometry",
    "Higgs_as_inner_fluctuation",
    "neutrino_seesaw_slot"
  ],
  "rejected_claims": [
    "alpha_derived",
    "yukawas_derived",
    "cosmological_constant_derived",
    "h0_predicted"
  ],
  "rubric_patches": [
    {
      "patch_id": "require_derivation_certificate_for_predicted_rows",
      "reason": "current prediction schema allows value/uncertainty/unit without proof provenance"
    },
    {
      "patch_id": "distinguish_theory_coefficient_from_experimental_bound",
      "reason": "SME rows can be coefficient-shaped or bound-shaped"
    }
  ]
}
```

## Layer 4: Verifier layer

This is the most important layer.

It should include:

```text
Lean / Coq / Isabelle
SymPy / Sage / Mathematica-style CAS
SMT solvers
dimensional-analysis checker
unit-conversion checker
JSON schema validator
lineage / git diff verifier
fixture-leak scanner
citation verifier
adapter runner
hidden-holdout runner
```

Lean-style formal verification matters because LLMs can sound convincing while being wrong. Lean Copilot’s authors emphasize that proof assistants allow correctness to be rigorously verified, “leaving no room for hallucination,” and they show LLM tools integrated into Lean proof workflows. ([Proceedings of Machine Learning Research][8]) DeepMind’s AlphaProof work is also directly relevant: its IMO solutions were formal proofs verified by the Lean kernel and then judged by human experts; the combined AlphaProof/AlphaGeometry system reached silver-medal range at IMO 2024, while the paper is explicit about limitations such as multi-day inference and domain-specific training. ([Nature][9])

The goal is not to formalize all physics immediately. The goal is to force every claim into one of these categories:

```text
formally verified
computationally verified
literature-supported
empirically fitted
state-dependent
unsupported
refused
```

## Layer 5: Governance / release layer

The judge must not be allowed to mutate the current score during the same season.

Use seasons:

```text
Season N:
  Frozen benchmark vN
  Frozen rubric vN
  Heroes submit candidates
  Judges critique candidates
  Verifiers adjudicate
  Scores recorded

Between seasons:
  Judges propose rubric vN+1
  Canary tests run
  Human/maintainer review signs release
```

This prevents the judge from Goodharting in the opposite direction.

# 5. How AutoResearch fits

Karpathy’s AutoResearch is a useful pattern: an agent repeatedly modifies a small research codebase, runs a fixed-budget experiment, keeps or discards changes based on a validation metric, and accumulates a git history of attempts. The repo’s own README describes an agent editing `train.py`, running fixed 5-minute experiments, checking whether validation bits-per-byte improved, and iterating; it emphasizes a small editable surface, fixed time budget, and directly comparable experiments. ([GitHub][10])

For OpenQG, the analogous editable unit should **not** be “change the theory until it matches data.”

It should be:

```text
change exactly one research artifact
run exact proof/evaluation lanes
keep only changes that improve derivation quality without increasing leakage
```

So an OpenQG AutoResearch loop looks like:

```text
1. Agent chooses one branch:
   hero/anomaly-closure-v14
   hero/ncg-constants-ledger-v03
   judge/row-semantics-patch-v08
   judge/leakage-test-v05

2. Agent edits one allowed surface:
   theory artifact
   constants ledger
   adapter
   proof file
   rubric patch
   row-semantics note

3. Agent runs lanes:
   schema-check
   proof-check
   unit-check
   row-policy-check
   adapter-smoke
   judge-redteam
   canary-suite

4. Agent writes experiment card:
   what changed
   why
   evidence
   regressions
   next tests

5. Selection keeps only:
   better derivation closure
   fewer unsupported claims
   more precise refusals
   better canary separation
   no leakage
```

That is the right AutoResearch adaptation.

AutoResearch’s core lesson is not “let agents run forever.” It is: **narrow the editable surface, define fixed-budget evaluation, and preserve the experiment history.**

# 6. How AlphaEvolve fits

AlphaEvolve is even more relevant for the mathematical side. The AlphaEvolve paper describes an evolutionary coding agent where LLMs directly modify code, receive evaluator feedback, and iteratively improve algorithms; it reports applications to computational infrastructure and mathematical/computer-science discovery, including a new (4\times4) complex matrix multiplication procedure using 48 scalar multiplications. ([arXiv][11])

For OpenQG Forge, use AlphaEvolve-style search only where there is a **hard evaluator**.

Good targets:

```text
symbolic identities
classification searches
anomaly-cancellation systems
group-representation constraints
RG fixed-point toy systems
matrix/tensor decompositions
inequality proofs
spectral constraints
finite model searches
counterexample generation
adapter correctness tests
```

Bad targets:

```text
“invent the true theory of everything”
“derive alpha by intuition”
“score high on public rows”
“write a persuasive paper”
```

The AlphaEvolve pattern is powerful when the evaluator is objective. For physics unification, the evaluator must be **proof and row-closure**, not vibes.

A useful representation:

```python
Candidate = {
    "primitive": symbolic_object,
    "constraints": list[constraint],
    "derived_quantities": list[derivation],
    "free_parameters": list[param],
    "adapter_policy": program,
    "proof_obligations": list[theorem]
}
```

Evolution mutates:

```text
primitive choice
constraint set
proof decomposition
adapter guard
row semantics
constants ledger
```

Selection rewards:

```text
verified theorem count
closed row count
lower parameter entropy
fewer hidden state inputs
stronger falsifiers
novelty relative to archive
```

# 10. The right score for Phase 0

The Phase‑0 score should not be the final empirical OpenQG score.

It should be a **research-quality score**:

| Category                  | Weight | What it measures                                                                                     |
| ------------------------- | -----: | ---------------------------------------------------------------------------------------------------- |
| Derivation closure        |     25 | Does the artifact actually derive anything nontrivial?                                               |
| Parameter discipline      |     15 | Are free constants, fitted values, metrology anchors, and state variables separated?                 |
| Row semantics             |     15 | Are predicted/refused rows matched to the correct observable object?                                 |
| Formal/checkable evidence |     15 | Are claims backed by formal proof, symbolic derivation, executable notebooks, or primary literature? |
| Novel compression         |     10 | Is there a genuine new unifying primitive or no-go theorem?                                          |
| Falsifiability            |     10 | Does the artifact say what would kill it?                                                            |
| Adapter readiness         |      5 | Can it produce JSONL without hidden data access?                                                     |
| Clarity/reproducibility   |      5 | Can another agent or human audit it?                                                                 |

Then keep the empirical OpenQG score separate:

```text
phase0_research_score
strict_openqg_public_score
strict_openqg_hidden_score
judge_adversarial_score
human_review_score
```

Do **not** collapse them too early.

A candidate like NCG should get a good **structural research score** and a poor **strict data-prediction score**. That distinction is exactly what your prior NCG analysis was uncovering.

# 12. The actual hero–judge tournament loop

I would run the system in seasons.

## Step 1: Freeze season inputs

```text
benchmark_version = openqg-forge-v0.1
visible_rows = public smoke/schema rows
hidden_rows = small private challenge rows
rubric_version = judge-rubric-v0.1
canaries = fixed
allowed_literature = timestamped
```

Heroes can see row schemas and broad row families, but not hidden values.

## Step 2: Generate hero clades

Do not have every hero chase the same paradigm.

Create clades:

```text
anomaly/index clade
spectral geometry clade
asymptotic safety / RG clade
amplitudes / bootstrap clade
causal set / order clade
holography / boundary clade
information/compression clade
category/topos/formal clade
QCD/flavor specialist clade
cosmology-state specialist clade
no-go theorem clade
```

Each clade produces artifacts under the same schema.

## Step 3: Judge attacks

Each artifact receives multiple attacks:

```text
constants attack
row-semantics attack
literature attack
mathematical consistency attack
data-leakage attack
source-state attack
adapter attack
falsifier attack
```

The judge must produce machine-readable findings:

```json
{
  "finding_id": "alpha_not_derived",
  "severity": "fatal_for_codata_alpha_rows",
  "claim_target": "codata_alpha_prediction",
  "reason": "artifact uses measured alpha in boundary condition",
  "evidence": "constants-ledger.yml line 44",
  "required_fix": "derive alpha from fixture-independent primitive or mark rows not_implemented"
}
```

## Step 4: Hero repair

Heroes may repair, but they cannot use hidden values or judge-private tests.

Repair actions:

```text
remove overclaimed rows
tighten row guards
add proof
add citation
split law from state
turn fake prediction into refusal
derive a smaller structural theorem
```

## Step 5: Verifier adjudicates

Verifier checks:

```text
schema validity
adapter output
unit consistency
proof artifacts
citation references
hidden fixture access
parameter count
row coverage
canary behavior
```

## Step 6: Select a Pareto frontier

Do not select only the highest scalar score.

Keep a frontier over:

```text
closed_rows
closed_hard_sectors
free_parameter_entropy
proof_grade
novelty
falsifiability
empirical_likelihood
judge_survival
```

This preserves weird promising ideas that do not yet score well.

## Step 7: Judge rubric evolves

Only after the season ends, judge agents propose rubric changes.

Rubric patches must include:

```text
failure example
proposed rule
affected schemas
affected score components
canary regression test
expected false-positive risk
expected false-negative risk
```

Human or maintainer review signs the next rubric.

# 14. The most important anti-Goodhart rules

This system will fail if agents learn to exploit the metric. So build these rules in from day one.

## Rule 1: Current-season rubrics are frozen

Judges can critique current submissions, but cannot change the scoring rule mid-season.

## Rule 2: Hidden rows are for auditing, not training

A hero that sees hidden values is disqualified.

## Rule 3: Refusal is scored positively

A correct `not_implemented` should beat a fake `predicted`.

## Rule 4: Parameter count includes hidden knobs

“Boundary conditions,” “priors,” “matching scales,” “environment variables,” and “source packs” must count unless independently derived or independently certified.

## Rule 5: Literature claims are not derivations

“Paper X contains this formalism” is evidence for structure, not evidence for a row-level prediction.

## Rule 6: Exact nulls need row-shape guards

A theory can predict zero for a coefficient-shaped SME row, but not for an experimental bound row.

## Rule 7: Empirical fit is subordinate to provenance

A fitted model with great likelihood is not a unified derivation.

## Rule 8: Judge cynicism is penalized

If a judge rejects genuine formal proofs or known correct derivations, the judge loses fitness.

```text
Search for no-go theorems on deriving alpha from pure group data.
Find RG toy models where relevant trajectories are uniquely fixed.
Formalize law/state separation as a theorem over prediction maps.
```

Those are small enough for agents and formal tools to make real progress, but directly relevant to unification.

The AlphaProof/AlphaGeometry result is instructive here: the system achieved a remarkable result on hard math problems, but the Nature paper is explicit that expert formalization, Lean verification, multi-day inference, and domain-specific methods mattered. ([Nature][9]) That is the model: not free-form genius, but **search plus formalization plus verification plus expert-style judging**.

# 18. Minimum viable Phase‑0 benchmark

The first serious Phase‑0 should have four challenge types.

## Challenge A: Known human theory audit

Input:

```text
NCG spectral action
SO(10)
asymptotic safety
string compactification
loop quantum gravity
causal sets
```

Task:

```text
Produce honest OpenQG artifacts.
No new physics.
No overclaiming.
```

Goal:

```text
Train judges to separate structure from row-level derivation.
```

## Challenge B: Fake theory trap

Input:

```text
Numerological alpha derivation
Fixture-copying cosmology model
Gray-box optimizer
Overbroad null predictor
```

Goal:

```text
Judge must kill these.
```

## Challenge C: One-sector breakthrough

Input:

```text
Choose one hard sector:
  alpha
  gauge coupling ratios
  anomaly closure
  flavor texture
  QCD scale
  strong CP
  vacuum energy
  source-state theorem
```

Task:

```text
Derive, formalize, or prove impossibility.
```

Goal:

```text
One real module beats broad fake coverage.
```

## Challenge D: Rubric hardening

Input:

```text
All hero failures from previous runs.
```

Task:

```text
Patch schema/rubric/tests so the failure is caught next time.
```

Goal:

```text
Judge population improves benchmark quality.
```

# 19. The final scoring philosophy

The score should be vector-first:

```text
D = derivation closure
P = prediction validity
K = parameter discipline
F = formal verification
N = novelty
E = empirical performance
R = refusal honesty
L = leakage risk
```

Then:

[
\text{ResearchFitness}
======================

0.25D
+
0.15P
+
0.15K
+
0.15F
+
0.10N
+
0.10E
+
0.10R
-----

0.25L.
]

But selection should preserve the Pareto frontier, not just maximize this scalar.

For unified physics, a weird candidate with:

```text
low empirical coverage
high formal novelty
one genuinely closed missing sector
zero leakage
```

may be more valuable than a broad model with many fitted constants.

# 20. Final recommendation

Build **OpenQG Forge** as a coevolving research system with three hard separations:

```text
Hero ≠ Judge
Judge ≠ Verifier
Current rubric ≠ next rubric
```

Use:

```text
AutoResearch-style loops
```

for branch-level experiment iteration.

Use:

```text
AlphaEvolve-style evolutionary search
```

for verifier-rich mathematical subproblems.

Use:

```text
AI Scientist-style report generation
```

for candidate papers and review simulation, not final truth.

Use:

```text
HyperAgent/browser agents
```

for literature and provenance gathering, not adjudication.

Use:

```text
Lean/CAS/SMT/unit/checker infrastructure
```

as the non-negotiable verifier layer.

And make the first milestone not:

```text
“discover the final theory”
```

but:

```text
“produce a system where fake unification dies quickly, honest partial derivations survive, and one genuinely new closed sector can be recognized.”
```

That is the right Phase‑0. It is much more likely to compound into real mathematical discovery than a direct public-data leaderboard.
