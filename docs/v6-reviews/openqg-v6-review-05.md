# Occam and parsimony economics

V6.1 correctly identifies that background drift must be priced twice: once in the human-readable parsimony component, and once in data-fit evidence. That is the right conceptual fix. The implementation, however, is still a coarse BIC proxy rather than a reliable marginal likelihood.

The parsimony count lives in `crates/openqg-core/src/theory/scorecard.rs::total_free_dof`, which delegates to `free_dof` plus `background_dof`. `background_dof` compares nine standard coordinates against `CosmologyParams::planck_lcdm()`: `h`, `omega_m`, `omega_b_h2`, `n_eff`, `sum_mnu`, `w0`, `wa`, `omega_k`, and `sigma8`. Any drift above `1e-9` counts as one dof. It intentionally excludes MG background fields such as `mu0`, f(R), and nDGP, because truth-binding is supposed to kill unexplained modifications and certified ones are derived.

This is a strong improvement over V5. The V5 champion moved `h`, `omega_m`, and `w0` for free. The V6.1 regression in `crates/openqg-bench/src/zyal_genome/physics_score.rs::v6_drift_tests::background_drift_costs_parsimony_dof` verifies those three moved dials count as three dof. The score component then computes `pars_raw = max(1 - free/4, 0)`, so zero dof gets 12/12, one gets 9/12, two gets 6/12, three gets 3/12, and four or more gets 0.

The good news: no, `k > 4` is not free again in data-fit. `crates/openqg-bench/src/zyal_genome/physics_score.rs::score_candidate` computes `k = openqg_core::total_free_dof(theory)` and subtracts `0.5 * k * ln(n_eff)` from `epsilon_delta_log_likelihood`. Even after the parsimony component saturates at zero, each extra counted dof continues to reduce `delta_lnz`. The old harmonic penalty problem is fixed.

The bad news: the dof count is binary and tolerance-based. A one-part-in-a-billion drift and a large physical drift both count as one dof. That is acceptable for "how many knobs did you move?" parsimony, but not for an Occam factor. Evidence depends on posterior width relative to prior volume, not merely on coordinate count. A parameter pinned by data with tiny posterior volume can pay a large Occam factor; a parameter nearly irrelevant to the likelihood should pay less. The archive already contains `crates/openqg-core/src/scoring/evidence.rs::laplace_log_evidence` and `grid_log_evidence`, but the live campaign path does not use them.

The effective sample size is also wrong. `score_candidate` sets `n_eff = observables.len()`. With covariance blocks, record count is not the number of independent modes. `crates/openqg-core/src/scoring/covariance.rs::score_metrics_cov` scores Planck distance priors and DESI BAO pairs as correlated blocks, but the BIC penalty still treats every observable record as an independent contribution. For a 3x3 compressed prior, the effective information content depends on the covariance eigenvalues and model derivatives. For supernova covariance, thousands of magnitudes do not equal thousands of independent cosmological modes after nuisance calibration and correlated systematics.

There is a related baseline inconsistency. `baseline_log_likelihood_cov` scores the Planck baseline with `parameter_count = 3` inside `score_metrics_cov`, but the campaign's `DataFitOutcome` compares a fixed candidate against that baseline and then subtracts only the candidate's `total_free_dof`. It does not profile-fit LambdaCDM and the challenger under the same parameter priors. The fair model-selection path in `crates/openqg-core/src/theory/league.rs::model_league` does profile-fit model classes and reports AIC/BIC, but the genome scorecard uses fixed theory instances.

The survivor exposes the economics problem. `run-data/v6-chunk-6-white-paper.json` reports `ndgp-proposed-fixed-rc` with `free_dof = 0`, `delta_lnz = -1.689`, and 12/12 parsimony. The binding report derives `ndgp_omega_rc = 0.7097` from `ndgp_geff_over_g`. Since the certificate fixes `beta = 2`, the system treats the nDGP crossover as costless. That is fair only if `beta = 2` is a true theoretical constant, not a post-search selected value. The code cannot yet distinguish a derived constant from a chosen model hyperparameter. `ParameterRole` exists in `theory/mod.rs`, but it is not wired into scoring.

V7 should separate three quantities: structural dof, fitted dof, and post-search choice count. `background_dof` is a structural drift counter. It should stay. Evidence should move to a league-style model comparison that profile-fits both baseline and candidate classes against the same data. For low-dimensional candidates, use `scoring/evidence.rs::laplace_log_evidence` with deterministic grid cross-checks over declared priors. For high-dimensional candidates, stamp the result as BIC-only and do not let it support external claims.

Specific file changes: update `physics_score.rs::score_candidate` to call a new `evidence_outcome_for(theory, observables, blocks)` that returns `delta_lnz`, `method`, `k_eff`, `n_eff`, `prior_volume`, and `boundary_hit`. Add `effective_modes(blocks, observables)` in `scoring/covariance.rs`, initially conservative: one mode per covariance block eigenvalue above a tolerance plus one per unblocked observable. Wire `ParameterRole::PostSearchChoice` into `total_free_dof` for certified relation inputs that were selected by the proposer, such as `beta = 2` or `a_drag = 2`, unless they are registered as fixed external constants.
