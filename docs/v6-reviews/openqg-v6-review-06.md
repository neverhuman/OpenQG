# Re-clothing operator post-fix

The re-clothing operator is now safer than V6, but it is still the campaign's dominant laundering pressure. The code path is `crates/openqg-bench/src/zyal_genome/theory_population.rs::reclothe_candidate`. It clones a donor `ProposalDoc`, grafts donor non-baseline parameters into an evolved descendant, refreshes any novel-prediction witnesses using the engine's forward model, and then the normal `score_proposal` path revalidates evidence, certificates, obligations, physics vetoes, and novelty audits. It no longer copies scorecard points. That is the correct architectural boundary.

V6.1 fixed two major laundering routes. First, if `openqg_core::background_dof(&doc.theory) > 0`, the operator drops the donor unification claim. That addresses the V6 pattern where a donor claimed `H0 = 67.4` unification while the descendant's background fit moved `h` to another value. Second, refreshed witnesses are marked `w.refreshed_by_engine = true`, and `scorecard.rs::score_with_observables` caps engine-refreshed out-of-fit novelty at 0.5. The audit record in `docs/V6-ACCEPTANCE.md` correctly identifies these as central V6.1 fixes.

The first remaining path is structural. Re-clothing grafts parameters, claims, obligations, unification, and evidence, but it does not graft action terms from the donor. It sets `doc.theory = descendant` after adding missing donor parameters. If the descendant has only baseline terms, and the donor parameter certificate binds an MG field, the current structural veto may not catch the missing generating term. That is exactly visible in `run-data/v6-chunk-6-white-paper.json`: `ndgp-proposed-fixed-rc` has terms `einstein_hilbert` and `cosmological_constant`, yet `binding.bindings` reports `ndgp_omega_rc` from `relation:ndgp_geff_over_g`.

The second remaining path is repeated lineage selection. The V6 champions listed in `docs/V6-CAMPAIGN-REPORT.md` are all `-rc` lineages: `thy-m86aa-rc-rc`, `thy-x7220-rc-rc-rc`, `thy-meea4-rc-rc`, `thy-m56e9-rc-rc-rc`, `thy-mbed0-rc-rc-rc-rc`, and `ndgp-proposed-fixed-rc`. V6.1 prevents direct point-copying, but repeated re-clothing still creates a privileged search channel: a donor structure that survives the current oracle gets sprayed over descendants until it finds a local scoring surface. That is not inherently wrong, but the campaign should price it as a search multiplicity.

The third path is witness refresh as an oracle adapter. `reclothe_candidate` recomputes witness `predicted` and `baseline` values from `BackgroundForwardModel`. That means a stale donor witness cannot fabricate values anymore. But it also means a re-clothed child gets an engine-authored witness for free, without the proposer naming a new falsification target or registering it before the descendant existed. The 0.5 tier is therefore too generous for chains like `-rc-rc-rc`, where the witness is a post-hoc fit annotation.

The fourth path is donor evidence drift. `score_proposal` content-binds evidence bytes, which is good. But evidence can be true for the donor and irrelevant to the descendant. A derivation file explaining nDGP `G_eff/G = 7/6` still verifies after grafting, but it may not justify the descendant's background, action terms, screening regime, or data claim. V7 needs obligation scopes: an obligation should declare which fields and terms it certifies, and re-clothing should drop claims whose scope no longer matches the descendant.

The fifth path is ID opacity. The `-rc` suffix records the operation in the theory id, but the scorecard does not carry a structured reclothe lineage count, donor id, donor score, or witness-refresh count. Downstream reviewers must infer from strings. A chain can hide in a renamed id if a future operator changes naming. The artifact should expose this as data.

V7 engineering changes should be concrete. In `theory_population.rs::reclothe_candidate`, after grafting parameters, also compute a `ReclotheReceipt` with `donor_id`, `descendant_id`, `rc_depth`, `grafted_parameters`, `dropped_unification`, `refreshed_witnesses`, and `dropped_claims`. Add it to `ProposalDoc` or `ScorecardV4` as non-scoring metadata. In `scorecard.rs`, set engine-refreshed novelty to 0 unless the witness was registered before the descendant fit; otherwise record it as `fit_explanation`.

Add donor gating before grafting. A donor should be eligible only if it passes current `physics_kills`, current `score_with_observables`, and a new structural-term audit. Do not allow donors with missing action terms to contribute parameters. Add a test where a donor with `ndgp_geff_over_g` but no `ndgp_brane` term fails re-clothing. Add another test where `-rc-rc-rc` receives no additional novelty unless every generation has a pre-registered out-of-fit witness.

Finally, move re-clothing from an always-positive operator to an explicitly costed search primitive. Track the number of re-clothing attempts in run summaries and apply a multiplicity penalty in model-selection reporting. The issue is not that re-clothing exists; the issue is that a structure-fit graft operator dominated the campaign and still has no statistical price.
