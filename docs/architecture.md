# Architecture

OpenQG is organized around a small set of explicit surfaces:

- `crates/openqg-core` owns typed manifests, scoring primitives, and validation helpers
- `crates/openqg-bench` owns CLI orchestration, benchmark execution, release packing, and generated artifact writing
- `crates/openqg-data` owns registry and lock validation
- `contracts/registry.yml` is the contract manifest
- `contracts/specs/` stores editable YAML schema specs that are regenerated by `just schema-sync`
- `contracts/generated/schemas/` stores the generated JSON schema outputs
- `python/ai-service` is the exception-only scientific adapter surface
- `agent/zyal` contains runnable research and maintenance loops

The intended flow is:

1. edit source manifests or code
2. run the narrow proof lane
3. regenerate generated artifacts through the declared command
4. record release evidence under `reports/releases/draft/`
