# Novel-prediction truth-audit

The V5 novelty audit is a necessary improvement, but its reward semantics are still gameable. `crates/openqg-core/src/theory/binding.rs::audit_novel_predictions` canonicalizes each witness observable, predicts it for the bound background and the Planck LCDM baseline, and records `computed_predicted`, `computed_baseline`, `computed_distinct`, and `honest`. `scorecard.rs` then awards full novelty if any audit is both computed-distinct and honest. That is the right shape.

The first problem is tolerance ownership. The audit sets `tolerance = w.min_detectable` and checks honesty with `abs(w.predicted - cp) <= tolerance` and `abs(w.baseline - cb) <= tolerance`. The same `min_detectable` is also used for distinctness: `abs(cp - cb) >= w.min_detectable`. This couples two different concepts. Experimental detectability should describe what a future instrument can resolve; honesty tolerance should describe how accurately the proposer reported the engine-computed value. An adversarial proposer can choose a large enough `min_detectable` to cover a fabricated number, provided it stays below the computed model-baseline difference. For large deviations this permits sloppy or biased witness numbers while still earning full novelty.

V6 should split the witness schema in `crates/openqg-core/src/theory/obligation.rs`: `min_detectable` remains an experimental claim, while `declared_value_tolerance` is engine-capped. If absent, use `max(1e-6, 0.01 * abs(computed_value))` or an observable-specific numerical floor from `BackgroundForwardModel`. A witness should not get to define the tolerance by which its own truthfulness is judged.

The second problem is demote-vs-kill. A computable but dishonest witness currently demotes novelty to zero, but the candidate can still score on data fit, robustness, and parsimony. For ordinary mistakes this is fine; for adversarial search it is too forgiving. If a witness names a computable observable and declares numbers outside the engine tolerance, that is not merely "no novelty"; it is a failed derivation obligation. Convert it to `VetoReason::UnverifiedDerivation` or a new `DishonestNovelPrediction` kill when the mismatch exceeds a hard bound. Minor rounding errors can demote; fabricated values should kill.

The third problem is uncomputable half-credit. In `scorecard.rs`, if all audits have `computed_distinct=None`, the candidate gets `nov_raw=0.5`. That rewards witnesses outside the model grammar, exactly where truth-audit cannot operate. The current tests even show `cl_tt_l220` canonicalizes to `None`. V6 should give zero novelty for uncomputable witnesses unless a separate external forward backend is declared and its manifest is attached. "The model cannot check it" must not be a reward class.

The observable grammar in `crates/openqg-core/src/cosmology/observables.rs` is reasonable for the background/growth model, but it has sharp edges. The suffix decoder maps `fsigma8_z10` to `fsigma8@1`, not `z=10`; that is documented in tests, but it is surprising. Use an explicit grammar for generated witnesses: prefer `name@0.51` only, deprecate `_z051` in proposer prompts, and reject ambiguous suffixes for novel-prediction obligations. The canonicalizer can still support legacy dataset aliases.

The fourth problem is alpha-only distinctness. `scorecard.rs::distinct_from_lcdm` treats any nonzero alpha modification as physical distinctness, but `BackgroundForwardModel` does not compute alpha-basis growth, lensing, or tensor observables. Therefore an alpha-jitter candidate can get half novelty with no witness and no computed consequence. Tie novelty eligibility to `binding_outcome.report.bound_non_gr` or to a model class whose observables are actually computed. Alpha-basis metadata alone should not count.

Finally, novelty should be per-observable and per-dataset, not a single binary. Add `NoveltyAuditVerdict::{ComputedHonestDistinct, ComputedHonestNotDistinct, ComputedDishonest, Uncomputable, AmbiguousObservable}` and store it in the scorecard. Full novelty should require at least one `ComputedHonestDistinct` on an observable not already in the training likelihood, or on a held-out data tier. If the witness repeats `s8` or `fsigma8@0.51` from the same admitted scoring suite, it is a good fit explanation, not a novel prediction.

This distinction matters for re-clothing too. When a claim graph is grafted onto an evolved descendant, every novel witness must be recomputed after binding. If the descendant changed `h`, `omega_m`, `w0`, `sigma8`, `mu0`, or the MG family, the old witness values are stale by construction. Treat stale witnesses as dirty obligations; they earn nothing until regenerated from the actual bound background and re-audited.
