# Executive review

V6.1 is a real hardening step. The important improvement is not that the campaign found a publishable cosmology; it did not. The improvement is that the archive now contains executable policy in the scoring path. `crates/openqg-core/src/theory/vetoes.rs::physics_kills` fuses triage and adjudication. `crates/openqg-core/src/theory/scorecard.rs::score_with_observables` is veto-first and context-aware. `crates/openqg-bench/src/zyal_genome/physics_score.rs::score_candidate` stamps likelihood mode and charges a BIC-style Occam term. `crates/openqg-core/src/theory/binding.rs::bind_modified_background` makes certified modified-gravity claims affect the actual background the forward model computes. Those are the right instincts.

The audit record in `docs/V6-ACCEPTANCE.md` and `docs/V6-CAMPAIGN-REPORT.md` is also unusually honest. It says V5 diagonal evidence became V6 covariance evidence, then V6.1 closed the apparent valley after the `cmb_lA` anchor calibration and drift Occam charge. It records that all six V6 campaign champions were re-clothed lineages and that five were disqualified by `StructurallyUngenerated`. That is exactly how this system should learn: a campaign discovers a self-hack, the next rubric turns it into a regression test.

But V6.1 is still a no-go for an external scientific campaign. It is a go for a V7 engineering campaign. The archive does not yet support a claim stronger than: "The current oracle rejects the known V4/V5/V6 reward hacks on the admitted compressed data." That is useful, but it is not modified cosmology.

Top risk 1: the anchor calibration is a constant offset. `crates/openqg-core/src/cosmology/forward.rs` defines `CMB_LA_ANCHOR_CALIBRATION` and `CMB_R_ANCHOR_CALIBRATION` as fixed differences at `CosmologyParams::planck_lcdm()`. The regression test proves the Planck anchor matches; it does not prove the residual is small away from the anchor. Since V6 exploits already lived in the derivative of `lA` with respect to `h`, this is the most dangerous remaining physics surface.

Top risk 2: the structural-generation veto is too narrow. `vetoes.rs::adjudicate` checks term-name substrings for dynamic `w0/wa` and alpha-basis deviations. It does not require an nDGP brane term when a certificate binds `ndgp_omega_rc`, nor an f(R) action term when `mg_family` is bound by `fr_alpha_m`. The survivor `ndgp-proposed-fixed-rc` in `run-data/v6-chunk-6-white-paper.json` has only `einstein_hilbert` and `cosmological_constant` terms, yet binding converts `geff_over_g` into `ndgp_omega_rc`.

Top risk 3: the claimed V6.1 survivor score is not reproduced in the run data. The prompt says `ndgp-proposed-fixed-rc` survives at 25.0, but `run-data/v6-chunk-6-white-paper.json` stores a V6-era scorecard at 60.0: 20 derivation, 15 unification, 13 robustness, 12 parsimony, zero data and novelty. The archive has no full proposal ledger or fixture data under `data/fixtures/...`, so a referee cannot reproduce the 25.0 rescore from the supplied artifacts alone.

Top risk 4: the Occam term is still a scalar approximation over `observables.len()`. `physics_score.rs::score_candidate` computes `0.5 * k * ln(n_eff)` with `n_eff = observables.len()`. With a Planck 3x3 compressed prior and DESI covariance blocks, the effective number of independent modes is not just record count. The code even has `crates/openqg-core/src/scoring/evidence.rs::laplace_log_evidence`, but the campaign path does not use it.

Top risk 5: the proposer can still learn the oracle, not the physics. `crates/openqg-bench/src/zyal_genome/proposer_router.rs::propose_one_sample` sends kill reasons into an oracle-repair prompt, including the engine-computed value for fabricated witnesses. That is transparent, but it teaches the model to copy the current oracle's numerical surface.

Recommendation: V7 should proceed only as a hardening campaign with no external physics claims. The V7 acceptance line should be reproducibility-first: include the full ledgers, fixture data, covariance files, and a machine-generated V6.1 rescore artifact for every V6 champion. The scientific go/no-go should wait for a Boltzmann-backed likelihood, a real term algebra, and out-of-fit-set prediction registration.

The most constructive read is that V6.1 has turned OpenQG into a useful adversarial instrument. It can discover which parts of the rubric are ambiguous enough for an optimizer to exploit. That is a serious engineering achievement. But the same history argues against trusting the current champion class: V4, V5, and V6 winners were each invalidated by the next audit. V7 should therefore measure success by how many exploits it makes impossible, not by whether a new high score appears.
