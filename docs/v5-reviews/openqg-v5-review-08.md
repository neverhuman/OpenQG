# Datasets and evidence

V5 needs a likelihood representation upgrade before another scientific campaign. The core already knows the right concept: `crates/openqg-core/src/scoring/covariance.rs` defines `LikelihoodData` and `CovarianceBlock`, and `score_metrics_cov` computes `-0.5 r^T C^-1 r`. The problem is integration. `crates/openqg-core/src/theory/evaluate.rs::evaluate` and `crates/openqg-bench/src/zyal_genome/physics_score.rs::baseline_log_likelihood` still call diagonal `score_metrics`. V6 should make covariance the default type and force diagonal data to declare itself as diagonal.

Implement this in `crates/openqg-data`, not as ad hoc JSON in the benchmark. Add `LikelihoodManifest` or extend `DatasetManifest` with `records_path`, `covariance_blocks`, `observable_order`, `matrix_path`, `matrix_format`, `units`, `citation`, `tier`, and `training_role`. A block should be self-contained: ordered IDs, covariance matrix, source citation, and whether the published covariance includes statistical-only or stat+sys errors. The loader should validate positive definiteness with the Cholesky routine already in `covariance.rs`.

The first dataset to admit is the full compressed CMB distance-prior covariance, not independent `cmb_R` and `cmb_lA`. `cosmology/forward.rs` already predicts `cmb_R`, `cmb_lA`, and `cmb_omega_b_h2`. The corresponding Planck 2018 distance-prior covariance should be one 3x3 block. Honest expected outcome: the h/Omega_m slide will lose much of its 55-nat advantage, because the allowed direction and width of the CMB prior are encoded by covariance, not independent residuals. It may not vanish until a Boltzmann backend is present, but it should stop saturating the data-fit score.

The second dataset class is BAO covariance. DESI/eBOSS/BOSS measurements often publish correlated `D_M/r_d` and `D_H/r_d` at a tracer redshift; treating them independently double-counts combinations. Represent each tracer bin as a block over `dm_over_rd@z` and `dh_over_rd@z`, or a scalar block for `dv_over_rd@z`. Do not mix releases without release-level covariance or a declared independence rationale.

The third class is SNe. `BackgroundForwardModel` predicts `mu@z`, so the model side is ready. The data side is not: Pantheon+/Union-style likelihoods require a full covariance matrix and nuisance handling. If V6 cannot load the full matrix efficiently, use compressed binned moduli with their covariance and clearly label the compression. Do not add hundreds of diagonal SNe points; that will swamp the score with fake precision.

The fourth class is BBN and early-universe anchors. `cosmology/forward.rs` predicts `bbn_yp`, `omega_b_h2`, `n_eff`, and `r_drag`. Add D/H, helium, and baryon-density priors with covariance where published. These discriminate early dark energy and sound-horizon tricks from late-time H0 shifts. They also help prevent the engine from solving H0 by moving early parameters in a way that breaks BBN.

The fifth class is growth at higher redshift and with survey covariance. The current inline V5 growth fixture includes `fsigma8@0.067`, `0.38`, `0.51`, `0.61`, `1.48`, and `s8`. Add redshift bins with covariance per survey and separate weak-lensing S8 blocks. For suppressed-growth mechanisms, high-z growth is critical: a late-time mu0 ansatz and a dark-sector drag model can match low-z S8 while diverging at `z > 1`.

The sixth class is laboratory and solar-system constraints. These should not enter as ordinary Gaussian cosmology points unless the forward model computes them. Put them in an adjudication tier: `Gdot/G`, lunar laser ranging, Cassini gamma, binary pulsars, equivalence-principle bounds, and GW170817. The code already has `vetoes.rs::adjudicate`; V6 should make it a required promotion gate and attach receipts.

Finally, every dataset needs a `training_role`: `fit`, `validation`, `holdout`, or `adjudication`. Novelty should only be earned on `holdout` or newly predicted observables, not on the same `fit` records used to optimize. Robustness should be computed by leave-one-survey-out and covariance stress, not by alternating indices through a correlated list.

The evidence store should also separate bibliographic evidence from numerical likelihood assets. `FsEvidenceStore` is good for content-binding claims, but dataset matrices need their own manifest hashes and validation receipts. A covariance matrix is not a prose citation; it is executable scoring input. Record its hash in the data lock, include the matrix order in the score receipt, and fail closed if an observable ID in the matrix does not canonicalize to the forward-model grammar.
