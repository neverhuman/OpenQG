## Ranked backlog

### 1. Demote AIC/BIC/Schwarz evidence to screening; require nested-sampling evidence for quoted ranking

**What:** In `docs/theory-league.md` and `crates/openqg-core/src/theory/league.rs`, define a two-tier league: a fast screening league may report profile likelihood, AIC, BIC, and approximate Schwarz/Laplace `ln Z`; the publication league must report nested-sampling Bayesian evidence with declared priors, nuisance treatment, and convergence diagnostics before any model ranking is quoted.

**Why it matters:** AIC/BIC are useful triage heuristics, not a trustworthy adjudicator for frontier physics claims. BIC assumes large-sample regular asymptotics and a particular unit-information prior interpretation. A Laplace/Schwarz approximation can be badly wrong for curved degeneracies, bounded parameters, multimodality, weak identification, non-Gaussian likelihoods, or models with hard vetoes. Those are exactly the regimes cosmology and evolved symbolic theories create. A referee will not accept “ΔlnZ” from a Schwarz approximation as real Bayesian evidence unless the posterior is demonstrably Gaussian and prior-insensitive.

**Effort:** L.

**Verify:** Add a nested-sampling backend adapter with deterministic seeded test cases: Gaussian linear model where analytic evidence is known; banana/curved posterior where Laplace fails; multimodal mixture where BIC fails; bounded prior case where evidence changes under prior width. A league report may expose `delta_aic`, `delta_bic`, and `schwarz_ln_z_screen`, but `ranked_for_publication=true` must be impossible unless nested evidence diagnostics pass.

### 2. Implement a model-search multiplicity ledger and look-elsewhere penalty

**What:** Add a search-pressure ledger in `crates/openqg-core/src/theory/evolve.rs`, `assessment.rs`, and `league.rs`: number of candidates generated, families explored, mutations attempted, failed candidates, reused ideas, effective independent trials, and selection path. Every champion report must include a post-selection adjustment or external validation run.

**Why it matters:** Evolutionary search changes inference. A model that wins after 50,000 generated candidates is not statistically comparable to ΛCDM as if it had been proposed once. Without accounting for search multiplicity, the league will discover scorecard overfits and call them theories. This is the most important honesty gap after evidence computation.

**Effort:** M/L.

**Verify:** Run null simulations where data are generated by ΛCDM but the evolution engine searches a broad model grammar. The false-discovery rate of “better than ΛCDM” must be calibrated and reported. Require champion shrinkage on a sealed holdout or posterior predictive validation set.

### 3. Add absolute goodness-of-fit and posterior predictive checks, not only relative comparison

**What:** Extend `crates/openqg-core/src/scoring/likelihood.rs` and `docs/theory-league.md` so every candidate reports χ², degrees of freedom/effective degrees of freedom, posterior predictive p-values, residual structure by dataset family, leave-one-survey-out checks, and failure modes.

**Why it matters:** A model can beat another bad model while still being bad. Relative ΔAIC/ΔlnZ does not answer whether the model is compatible with the data-generating process or whether residuals show systematic structure. For a serious physicist, absolute fit quality is not optional.

**Effort:** M.

**Verify:** Add fixtures where two models are both wrong but one has lower AIC; reports must mark both as poor absolute fits. Add residual plots or machine-readable residual summaries by source family: SN, BAO, H0, RSD/growth, CMB distance-prior proxy if present.

### 4. Require a covariance provenance registry and forbid silent diagonal likelihood substitution

**What:** Harden `crates/openqg-core/src/scoring/covariance.rs` and `docs/architecture.md` with a covariance registry: source ID, observable vector ordering, units, covariance matrix hash, positive-definiteness check, conditioning treatment, nuisance parameters, and citation/provenance. If only diagonal errors are available, reports must label the result “screening only” unless a documented approximation is justified.

**Why it matters:** The prompt says the project already recognizes diagonal-vs-covariance limitations. That is good, but not enough. Diagonal likelihoods can overweight correlated data, exaggerate tension, and manufacture improvements. The corrected `+36.7` artifact is credible only if the covariance correction is mechanically enforced and auditable.

**Effort:** M.

**Verify:** Add a known correlated synthetic dataset. Diagonal scoring should produce an inflated Δ score; covariance scoring should recover the known truth. CI should fail if a dataset with declared covariance is scored diagonally without an explicit `screening_only` flag.

### 5. Split nuisance, calibration, physical, derived, and post-search parameters

**What:** Introduce a parameter taxonomy in `crates/openqg-core/src/theory/mod.rs`, `unification.rs`, `evaluate.rs`, and `league.rs`: `derived_constant`, `fixed_external_anchor`, `physical_free_parameter`, `nuisance_parameter`, `calibration_parameter`, `post_search_choice`, and `forbidden_fixture_value`. Complexity penalties and priors must differ by class, and reports must show counts by class.

**Why it matters:** “Derived-not-fit binds form but not parameter values” is a strong honesty slogan, but a referee will ask exactly which numbers are actually derived. A model with one physical parameter and twenty nuisance calibration knobs is not a one-parameter theory. A symbolic form discovered after search has an unpriced “grammar choice” unless the search path is penalized.

**Effort:** M.

**Verify:** A candidate cannot claim a derived-theory score when any target-row value came from validation fixtures or post-hoc calibration. Add tests where the same numeric knob is mislabeled; the report must fail closed.

### 6. Add ranking uncertainty, not just parameter uncertainty

**What:** The league should return a distribution over ranks, pairwise win probabilities, and sensitivity to priors/covariances/dataset removals. A champion should be reported as “rank 1 with P=0.62 under current priors; rank instability high” when appropriate.

**Why it matters:** Frontier model ranking is not a deterministic scoreboard once data uncertainty, priors, covariance, search pressure, and nuisance marginalization are acknowledged. Reporting a single ordered list overstates certainty and encourages leaderboard gaming.

**Effort:** M.

**Verify:** Bootstrap or posterior predictive resampling tests where top two models are statistically indistinguishable. The report must show rank uncertainty and avoid declaring a winner.

### 7. Make blinding and sealed holdouts first-class run contracts

**What:** In `docs/ZYAL.md`, `docs/production-run-1000.md`, and `ZYAL/runs/run-hybrid-1000-v2.zyal`, require blinded splits: visible development data, frozen public validation, sealed internal holdout, and post-champion one-shot evaluation. LLM agents must not see holdout rows, labels, residuals, or score deltas.

**Why it matters:** LLM-driven evolutionary search is a score optimizer. If agents see the same rows and score deltas repeatedly, “honesty anchors” become training signals. A sealed holdout is the simplest defense against accidental overfitting and prompt-level leakage.

**Effort:** M.

**Verify:** Taint tests: insert sentinel fixture constants into validation-only rows; any agent artifact or candidate expression containing the sentinel fails the run. Replay from artifacts must not require hidden prompts or private state.

### 8. Calibrate honesty anchors and decoys as statistical instruments

**What:** Expand `crates/openqg-core/src/theory/anchors.rs` and `adversary.rs` so anchors/decoys have measured sensitivity and specificity. Include easy ΛCDM baseline anchors, wrong-but-flexible decoys, leakage traps, overfit grammar traps, covariance traps, and prior-volume traps.

**Why it matters:** Anchors are only useful if calibrated. An honesty system that passes its own hand-picked decoys may still fail on real adversarial leakage or flexible-but-wrong theories. The project needs an operating characteristic curve for its “honesty” gates.

**Effort:** M.

**Verify:** Build a decoy suite with expected verdicts. Report false accept and false reject rates. The suite should include decoys that beat ΛCDM under diagonal likelihood but fail under covariance or holdout.

### 9. Upgrade the forward model before allowing cosmology claims beyond background+growth

**What:** Keep the current background+growth engine as a fast lane, but label it explicitly as incapable of full CMB or precision large-scale-structure adjudication. Add an interface to a Boltzmann solver or validated emulator before scoring EDE, coupled-DE, neutrino-mass, modified-gravity, or unification-motivated cosmologies as more than screening.

**Why it matters:** The prompt acknowledges “no Boltzmann CMB.” That limitation is decisive. Background distances plus growth approximations can triage, but cannot honestly adjudicate many cosmological models. EDE and coupled-DE specifically change perturbations and CMB observables; scoring them without the right forward model is misleading.

**Effort:** L.

**Verify:** Compare ΛCDM and wCDM outputs against CLASS/CAMB or a documented benchmark across H(z), distances, fσ8, and CMB distance priors. For any model requiring perturbation physics not implemented, reports must show `scoreable=false` or `screening_only=true`.

### 10. Create a referee-facing “model card” for every candidate

**What:** Each model report should include action/equations, assumptions, parameter ledger, priors, data used, data withheld, covariance status, nuisance treatment, evidence method, search history, vetoes, absolute fit, residuals, ranking uncertainty, and falsifiers.

**Why it matters:** The project’s trust claim is “whitebox, derived-not-fit.” A whitebox system must let a physicist audit the path from theory to observable to likelihood to ranking without reading all code.

**Effort:** M.

**Verify:** Snapshot-test a model card for ΛCDM, a wrong decoy, and an evolved candidate. A reviewer should be able to reproduce the score from the card plus machine-readable artifacts.

### 11. Define a minimum viable publication gate

**What:** Add a formal gate in `docs/theory-league.md`: no public claim of model preference unless covariance status, nested evidence, prior sensitivity, look-elsewhere accounting, absolute GOF, sealed holdout, and reproducibility receipts pass.

**Why it matters:** The most dangerous failure mode is a polished league table that outruns its methodology. A hard gate protects the project’s credibility.

**Effort:** S/M.

**Verify:** CI fixture: a model with excellent AIC but no nested evidence must be rejected for publication ranking.

### 12. Harden software reproducibility and numerical correctness

**What:** Add deterministic seeds, version-locked data manifests, exact binary/toolchain receipts, tolerance budgets, matrix conditioning diagnostics, finite-difference gradient checks if gradients are used, and independent reimplementation smoke tests.

**Why it matters:** Numerical cosmology bugs can masquerade as physics. Reproducibility is not just build hygiene; it is part of the statistical claim.

**Effort:** M.

**Verify:** Re-running the same league on a clean machine should produce byte-stable summaries or bounded numeric diffs. Perturbing solver tolerances should not change ranking except where marked unstable.

## Data sources

The data layer needs to become a statistical object, not a list of JSONL rows. The selected fixture files named in the prompt — `data/fixtures/cosmology/tier0-combined.jsonl`, `growth-rsd.jsonl`, and `sh0es-h0.jsonl` — should be treated as miniature examples of a broader data contract. Each row needs observable name, units, redshift or scale metadata, provenance, publication version, estimator definition, covariance block ID, whether the row is a direct measurement or derived summary statistic, and whether it is safe for development, validation, or sealed holdout.

Do not let source-state information become a theory prediction. H0 from SH0ES, RSD `fσ8`, BAO distances, supernova compressed parameters, and CMB distance priors are estimator products with method-specific assumptions. A candidate can fit or predict the observable only through a declared forward model and likelihood. It cannot quote the source value back as a “derived” result.

Minimum data apparatus:

1. A `data_registry.toml` or equivalent with row families, provenance hashes, split assignment, covariance links, and license/publication notes.
2. A covariance block format with explicit observable ordering, units, conditioning, and positive-definite repair policy.
3. A split policy: development rows visible to agents; validation scores visible only through coarse aggregate receipts; sealed holdout rows invisible until champion freeze.
4. A dataset-ablation protocol: leave out SH0ES, leave out growth, leave out BAO/SN family, leave out each survey. Report whether the model survives or is driven by one tension.
5. Synthetic truth datasets generated from ΛCDM and from known alternatives. These are essential for calibrating false discovery under evolutionary search.

Verification should be hostile: deliberately shuffle covariance row order and ensure tests fail; inject a hidden fixture constant into a validation row and ensure it cannot appear in artifacts; remove a high-leverage data family and ensure the ranking uncertainty expands.

## Forward-model fidelity

A background+growth engine is a good prototype and a dangerous production adjudicator. It can honestly score simple late-time expansion and approximate growth questions. It cannot honestly settle early-universe models, full CMB physics, neutrino hierarchy effects, EDE, coupled dark energy, gravitational slip, screening, or many quantum-gravity-motivated cosmologies without additional perturbation and Boltzmann machinery.

The forward model should therefore advertise capability tiers:

- **Tier F0: analytic smoke.** Closed-form or simple numerical H(z), distances, and approximate growth. Screening only.
- **Tier F1: background + linear growth.** Adequate for simple ΛCDM/wCDM/limited growth-index comparisons with covariance caveats.
- **Tier F2: Boltzmann-validated.** CLASS/CAMB parity or validated emulator for CMB and matter power summaries.
- **Tier F3: model-specific perturbations.** Required for EDE, coupled dark energy, modified gravity, gravitational slip, massive neutrinos beyond compressed approximations, or unification-motivated dynamics.

Every theory module in `crates/openqg-core/src/cosmology/background.rs`, `growth.rs`, and `forward.rs` should declare its tier and invalid observables. If a candidate touches an observable outside its tier, the report should refuse rather than extrapolate. Refusal is not failure; it is scientific honesty.

## Statistical rigor

The minimum referee-trust apparatus is:

1. **Full likelihood specification.** Gaussian only when justified; otherwise use the measurement likelihood or a validated approximation. Include covariance and nuisance terms.
2. **Nested evidence for rankings.** Profile likelihood, AIC, BIC, and Schwarz/Laplace evidence are screening diagnostics. Publication ranking requires nested sampling or another validated marginal likelihood method with priors.
3. **Prior registry.** Priors must be declared before scoring, with physical justification and sensitivity runs. Evidence without priors is not evidence.
4. **Nuisance marginalization.** Nuisance parameters should be marginalized, not merely profiled, unless the report is explicitly profile-only screening.
5. **Post-selection correction.** Evolutionary search must account for number and structure of trials. Champion scores require sealed holdout or calibrated false-discovery correction.
6. **Absolute goodness-of-fit.** χ², residuals, posterior predictive checks, and dataset-specific diagnostics are mandatory.
7. **Ranking uncertainty.** Report posterior rank probabilities or bootstrap rank stability.
8. **Blinding.** Agents cannot see holdout rows or fine-grained score gradients for validation data.

On the `+36.7` correction: the argument described in the prompt — re-fit the baseline, use covariance, apply complexity penalties — is directionally sound. It fixes the classic failure where a new candidate is compared against a stale or underfit baseline, scored with overconfident diagonal errors, and rewarded for flexibility. But the corrected ΔAIC/ΔlnZ numbers can still mislead if the likelihood is non-Gaussian, the covariance is incomplete, the baseline and candidate have different nuisance structures, priors are undeclared, parameter boundaries matter, the posterior is multimodal, or the champion was selected after extensive search. The fix should be framed as “the previous headline was invalid; the current screening result is less wrong,” not as final evidence.

## Theory coverage and attainable unified-physics target

The project should resist the temptation to chase “full unification” directly through low-dimensional cosmology rows. A background+growth dataset cannot validate quantum gravity, Standard Model constants, black-hole microphysics, or a unique high-energy completion. The best attainable target is an **IR bridge program**: derive low-energy cosmological/gravitational phenomenology from a constrained action, score only the observables that the implemented forward model can actually compute, and refuse every unsupported high-energy claim.

Most worth chasing on attainable data: a restricted scalar-tensor / EFT-of-dark-energy / modified-growth target with explicit action, stability conditions, gravitational-wave speed constraints, background expansion, linear growth, and falsifiable deviations from ΛCDM. This is not “the theory of everything.” It is a legitimate frontier-adjacent bridge because many unification ideas reduce to IR extra fields, running couplings, modified gravity, or consistency constraints. The program is concrete:

1. Define the action and allowed operator subset before search.
2. Declare priors and stability/causality vetoes.
3. Implement background and perturbation equations or mark the model unscoreable.
4. Include hard external constraints such as luminal gravitational-wave propagation where applicable.
5. Score ΛCDM, wCDM, growth-index, and the restricted target under the same data and priors.
6. Require nested evidence and sealed holdout before claiming preference.
7. Report falsifiers: data patterns that would kill the model, not just improve the score.

The derived-not-fit discipline should be strict: a candidate earns theory credit only for values or relations that follow from its declared primitive objects and equations. Fitted cosmological parameters can be legitimate physical parameters, but they are not derived constants. Post-hoc selected functional forms should carry search penalties.

## ZYAL multi-agent design

The ZYAL design should assume every agent is a potential overfitting engine. The deterministic host must own data splits, taint tracking, scoring, promotion, vetoes, receipts, and final reports. LLM lanes may propose equations, derivations, priors, objections, and code patches. They must not decide promotion, rewrite scores, see holdout rows, or write durable memory without host validation.

Required lanes:

- **Builder:** proposes candidate forms and derivations.
- **Statistician:** audits likelihoods, priors, nuisance parameters, and evidence method.
- **Data auditor:** checks provenance, covariance, splits, leakage, and row semantics.
- **Forward-model auditor:** checks whether observables are actually computable.
- **Adversary:** tries to find leakage, overfitting, parameter laundering, and decoy wins.
- **Reproducer:** re-runs from artifacts only.
- **Meta-judge:** audits whether the judge rewarded score hacking.

Required artifacts: claim ledger, parameter ledger, data ledger, covariance ledger, prior ledger, likelihood ledger, search ledger, veto ledger, residual report, rank-uncertainty report, reproducer receipt, and negative-memory capsule. Negative memory is important: failed candidates, leakage tricks, and invalid approximations should be remembered so future runs do not rediscover them.

## Software and reproducibility

Rust should own durable policy, config, tar validation, receipts, and run contracts. TypeScript should remain limited to dashboard/browser surfaces. For the Rust core paths named in the prompt, the main hardening work is not UI; it is invariant enforcement.

Minimum software gates:

1. No result artifact without a content-addressed run manifest.
2. No publication ranking without nested evidence diagnostics.
3. No covariance mismatch without hard failure.
4. No hidden data split mutation after run start.
5. No candidate promotion if a fixture constant appears in source, prompt, artifact, or memory.
6. No model card unless all ledgers are present.
7. No nondeterministic report diffs outside declared numeric tolerance.
8. No local paths, secrets, prompts, logs, browser profiles, downloaded archives, or private runtime state in committed outputs.

The mapped proof lane should include unit tests for scoring math, property tests for covariance ordering and matrix conditioning, integration tests for blinded ZYAL runs, snapshot tests for model cards, and replay tests that rebuild the reviewer packet from artifacts only. The standard should be simple: if a skeptical physicist cannot reproduce why a model ranked where it ranked, the engine has not earned trust.

## Minimum apparatus before a result deserves referee trust

Before any OpenQG result is described as a model preference rather than a screening curiosity, require all of the following:

- frozen data registry and split manifest;
- covariance-complete likelihood or explicit screening-only label;
- declared priors and nuisance model;
- nested-sampling evidence with convergence checks;
- AIC/BIC/profile likelihood clearly labeled as diagnostics;
- absolute goodness-of-fit and residual diagnostics;
- posterior predictive checks;
- search multiplicity ledger and post-selection correction;
- sealed holdout or independent validation;
- ranking uncertainty;
- sensitivity to priors, covariance choices, and dataset ablations;
- model card with equations, assumptions, parameter origins, and falsifiers;
- deterministic artifact replay receipt.

Until that exists, the honest headline is: **OpenQG is a promising evidence-gated screening and governance engine, not yet a trustworthy model-ranking authority.** That is not an insult. It is the line that keeps the project credible long enough to become worthy of serious physicists.
